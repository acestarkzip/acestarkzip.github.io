## 📕 B. Linux 권한, 프로세스, 패키지 (2026.10.13 Tue)

<a name="notion-heading-40ad9e129df780f299a6d4e14b9362f7"></a>

### 📃 a. User (유저/사용자)

**1. 개념**

- User는 리눅스 시스템을 사용하는 개별 사용자를 의미한다.
- 리눅스는 여러 사용자가 하나의 컴퓨터를 함께 사용할 수 있는 다중 사용자(Multi-user) 운영체제이다.
- 각 사용자는 고유한 사용자 ID(UID)를 가지고 있으며, 사용자마다 접근할 수 있는 파일과 실행할 수 있는 명령에 차이가 있다.
- 시스템 설정 변경이나 프로그램 설치 등 관리자 권한이 필요한 작업은 `root` 또는 `sudo`를 통해 수행한다.

**2. 주요 사용자 유형**

| 구분 | 설명 |
| --- | --- |
| root | 시스템 전체를 관리할 수 있는 최고 관리자 계정 |
| 일반 사용자 | 할당된 권한 범위 내에서 시스템을 사용하는 계정 |
| 시스템 사용자 | 서비스나 프로그램을 실행하기 위해 사용하는 계정 |

**3. 주요 명령어**

| 명령어 | 설명 |
| --- | --- |
| `whoami` | 현재 로그인한 사용자 확인 |
| `id` | 현재 사용자의 UID, GID 및 그룹 정보 확인 |
| `users` | 현재 로그인한 사용자 목록 확인 |
| `who` | 로그인한 사용자와 접속 정보 확인 |
| `sudo` | 관리자 권한으로 명령어 실행 |
| `su` | 다른 사용자 계정으로 전환 |

**4. 명령어 실습**

```text
# 현재 사용자 확인
whoami

# 사용자 ID와 그룹 정보 확인
id

# 관리자 권한으로 명령 실행
sudo apt update

# root 사용자로 전환
sudo su
```

**5. 핵심 정리**

- `root`는 리눅스의 최고 관리자 계정이다.
- `sudo`는 일반 사용자가 특정 명령을 관리자 권한으로 실행하도록 해준다.
- `UID`는 사용자 식별 번호이며, 일반적으로 root의 UID는 `0`이다.

### 📃 b. File Permission (파일 권한)

**1. 개념**

- File Permission은 파일이나 디렉터리에 대한 접근 권한을 의미한다.
- 리눅스에서는 사용자(User), 그룹(Group), 기타 사용자(Others)를 기준으로 권한을 구분한다.
- 파일을 읽거나 수정하거나 실행할 수 있는 권한을 각각 설정할 수 있다.

**2. 권한의 종류**

| 권한 | 기호 | 숫자 | 파일에서의 의미 | 디렉터리에서의 의미 |
| --- | --- | --- | --- | --- |
| Read | `r` | 4 | 파일 내용 읽기 | 디렉터리 내부 목록 확인 |
| Write | `w` | 2 | 파일 내용 수정 | 파일 및 디렉터리 생성·삭제·이름 변경 |
| Execute | `x` | 1 | 파일 실행 | 디렉터리 접근 및 내부 항목 탐색 |

**3. 권한 표시 방법**

다음 명령어를 통해 파일 및 디렉터리의 권한을 확인할 수 있다.

```text
ls -l
```

출력 예시:

```text
-rwxr-xr-- 1 user group 1024 Oct 13 10:00 test.sh
```

권한 부분인 `-rwxr-xr--`는 다음과 같이 구분된다.

| 구분 | 값 | 의미 |
| --- | --- | --- |
| 파일 유형 | `-` | 일반 파일 |
| User | `rwx` | 읽기, 쓰기, 실행 가능 |
| Group | `r-x` | 읽기, 실행 가능 |
| Others | `r--` | 읽기만 가능 |

※ 첫 번째 문자는 파일 유형을 의미한다. 일반 파일은 `-`, 디렉터리는 `d`로 표시된다.

**4. 숫자를 이용한 권한 설정**

권한은 `r=4`, `w=2`, `x=1`의 숫자를 더해서 표현할 수 있다.

| 권한 | 계산 | 숫자 |
| --- | --- | --- |
| `rwx` | 4 + 2 + 1 | 7 |
| `rw-` | 4 + 2 | 6 |
| `r-x` | 4 + 1 | 5 |
| `r--` | 4 | 4 |
| `-wx` | 2 + 1 | 3 |
| `-w-` | 2 | 2 |
| `--x` | 1 | 1 |
| `---` | 권한 없음 | 0 |

예시:

- `755` : 소유자는 모든 권한, 그룹과 기타 사용자는 읽기 및 실행 권한
- `644` : 소유자는 읽기 및 쓰기 권한, 그룹과 기타 사용자는 읽기 권한
- `700` : 소유자만 읽기, 쓰기 및 실행 권한

**5. 주요 명령어**

| 명령어 | 설명 |
| --- | --- |
| `ls -l` | 파일 및 디렉터리 권한 확인 |
| `chmod` | 파일 및 디렉터리 권한 변경 |
| `chown` | 파일 및 디렉터리 소유자 변경 |
| `chgrp` | 파일 및 디렉터리 그룹 변경 |

**6. 명령어 실습**

```text
# 파일 권한 확인
ls -l test.sh

# 소유자에게 실행 권한 추가
chmod u+x test.sh

# 권한을 755로 변경
chmod 755 test.sh

# 권한을 644로 변경
chmod 644 test.txt

# 파일 소유자를 user로 변경
sudo chown user test.txt

# 파일 소유자와 그룹을 함께 변경
sudo chown user:group test.txt
```

**7. 핵심 정리**

- `chmod`는 권한(Permission)을 변경한다.
- `chown`은 소유자(Owner)를 변경한다.
- `chgrp`는 소속 그룹(Group)을 변경한다.
- 권한 설정은 시스템 보안과 사용자별 접근 제어에 중요하다.

### 📃 c. Group (그룹)

**1. 개념**

- Group은 여러 사용자를 하나의 단위로 묶어서 관리하는 기능이다.
- 같은 그룹에 속한 사용자들은 그룹에 부여된 파일 및 디렉터리 권한을 공유할 수 있다.
- 여러 사용자가 동일한 프로젝트나 시스템 자원을 함께 사용하는 환경에서 유용하다.
- 각 그룹은 고유한 그룹 ID(GID)를 가진다.

**2. 그룹의 종류**

| 구분 | 설명 |
| --- | --- |
| Primary Group | 사용자가 기본적으로 소속되는 주 그룹 |
| Secondary Group | 사용자가 추가로 소속될 수 있는 보조 그룹 |

**3. 주요 명령어**

| 명령어 | 설명 |
| --- | --- |
| `groups` | 현재 사용자의 그룹 확인 |
| `id` | 사용자 및 그룹 ID 확인 |
| `groupadd` | 새로운 그룹 생성 |
| `groupdel` | 그룹 삭제 |
| `usermod` | 사용자 계정 정보 수정 |
| `gpasswd` | 그룹 구성원 및 그룹 암호 관리 |
| `getent group` | 시스템 그룹 정보 확인 |

**4. 명령어 실습**

```text
# 현재 사용자가 속한 그룹 확인
groups

# 사용자 및 그룹 정보 확인
id

# 새로운 그룹 생성
sudo groupadd robotics

# 사용자 user를 robotics 그룹에 추가
sudo usermod -aG robotics user

# 그룹 정보 확인
getent group robotics

# 그룹 삭제
sudo groupdel robotics
```

※ `usermod -aG`에서 `-a`는 기존 그룹을 유지하면서 추가한다는 의미다. `-a` 없이 `-G`만 사용하면 기존 보조 그룹 목록이 교체될 수 있으므로 주의한다.

**5. User와 Group의 관계**

예를 들어 `robotics`라는 그룹에 `user1`, `user2`, `user3`이 소속되어 있다고 가정한다.

- `user1`, `user2`, `user3`은 같은 그룹에 속한다.
- 특정 디렉터리의 그룹을 `robotics`로 지정할 수 있다.
- 그룹에 읽기 및 쓰기 권한을 부여하면 해당 그룹의 구성원들이 공동으로 사용할 수 있다.

```text
# 디렉터리의 그룹을 robotics로 변경
sudo chgrp robotics project

# 그룹에 읽기, 쓰기 및 실행 권한 부여
sudo chmod 770 project
```

**6. 핵심 정리**

- User는 개별 사용자 계정이다.
- Group은 여러 사용자를 하나로 묶어 권한을 관리하는 단위다.
- UID는 사용자 ID, GID는 그룹 ID를 의미한다.
- 그룹을 활용하면 여러 사용자의 파일 접근 권한을 효율적으로 관리할 수 있다.

### 📃 d. Processes (프로세스)

**1. 개념**

- Process는 실행 중인 프로그램을 의미한다.
- 프로그램은 디스크에 저장된 실행 파일이고, 프로세스는 해당 프로그램이 실행되면서 메모리와 CPU 등의 시스템 자원을 사용하는 상태를 말한다.
- 하나의 프로그램에서 여러 프로세스가 생성될 수 있다.
- 리눅스는 여러 프로세스를 동시에 실행하고 관리한다.

**2. 프로세스의 주요 정보**

| 용어 | 설명 |
| --- | --- |
| PID | Process ID. 프로세스 고유 식별 번호 |
| PPID | Parent Process ID. 부모 프로세스의 ID |
| USER | 해당 프로세스를 실행한 사용자 |
| CPU | 프로세스가 사용하는 CPU 자원 |
| MEM | 프로세스가 사용하는 메모리 |
| STATUS | 프로세스의 현재 상태 |

**3. 프로세스 상태**

| 상태 | 기호 | 설명 |
| --- | --- | --- |
| Running | R | CPU에서 실행 중이거나 실행 대기 중 |
| Sleeping | S | 이벤트나 작업을 기다리는 상태 |
| Uninterruptible Sleep | D | 일반적으로 I/O 작업을 기다리는 상태 |
| Stopped | T | 실행이 일시 정지된 상태 |
| Zombie | Z | 실행은 종료됐지만 부모 프로세스가 종료 상태를 아직 회수하지 않은 상태 |

**4. 주요 명령어**

| 명령어 | 설명 |
| --- | --- |
| `ps` | 프로세스 정보 확인 |
| `ps aux` | 시스템 전체 프로세스 목록 확인 |
| `top` | CPU 및 메모리 사용량 등 실시간 확인 |
| `htop` | 프로세스 상태를 직관적으로 확인하는 도구 |
| `pgrep` | 프로세스 이름 등을 기준으로 PID 검색 |
| `kill` | PID를 지정해 프로세스에 시그널 전송 |
| `killall` | 이름을 기준으로 프로세스에 시그널 전송 |
| `jobs` | 현재 셸에서 실행하거나 중지한 작업 확인 |
| `bg` | 작업을 백그라운드에서 실행 |
| `fg` | 작업을 포그라운드로 가져오기 |

**5. 명령어 실습**

```text
# 현재 터미널과 관련된 프로세스 확인
ps

# 시스템 전체 프로세스 확인
ps aux

# 실시간 프로세스 및 자원 사용량 확인
top

# 프로세스 이름으로 PID 검색
pgrep python

# PID가 1234인 프로세스에 종료 요청
kill 1234

# 강제 종료 시그널 전송
kill -9 1234
```

**6. Foreground와 Background**

프로세스는 실행 방식에 따라 포그라운드와 백그라운드로 구분할 수 있다.

| 구분 | 설명 |
| --- | --- |
| Foreground | 현재 터미널에서 실행되며 작업이 끝나기 전까지 터미널 입력을 점유 |
| Background | 터미널의 입력을 점유하지 않고 뒤에서 실행 |

```text
# 포그라운드 실행
python script.py

# 백그라운드 실행
python script.py &

# 현재 셸의 작업 목록 확인
jobs

# 작업을 백그라운드로 전환
bg

# 작업을 포그라운드로 전환
fg
```

**7. 프로세스 종료**

`kill`은 프로세스를 종료하거나 특정 동작을 요청하기 위해 시그널(Signal)을 전달하는 명령어다.

| 시그널 | 번호 | 설명 |
| --- | --- | --- |
| SIGTERM | 15 | 정상적인 종료 요청. 기본 `kill` 동작 |
| SIGKILL | 9 | 프로세스를 강제로 종료 |
| SIGSTOP | 19 | 프로세스를 일시 정지 |
| SIGCONT | 18 | 정지된 프로세스 재개 |

※ 프로세스 종료 시에는 먼저 `kill PID`를 사용하여 정상 종료를 요청하고, 종료되지 않는 경우에만 `kill -9 PID`를 사용하는 것이 좋다.

**8. 핵심 정리**

- Process는 실행 중인 프로그램이다.
- PID는 각각의 프로세스를 구분하는 고유 번호다.
- `ps`와 `top`은 프로세스 상태 및 자원 사용량을 확인할 때 사용한다.
- `kill`은 프로세스에 종료 등의 시그널을 전달한다.
- Foreground는 현재 터미널에서 실행하고, Background는 뒤에서 실행한다.

### 📃 e. Package (패키지)

**1. 개념**

- Package는 프로그램을 설치하고 관리할 수 있도록 필요한 파일과 정보를 하나로 묶어 놓은 단위다.
- 일반적으로 실행 파일, 라이브러리, 설정 파일 및 설치 정보 등이 포함될 수 있다.
- 리눅스에서는 패키지 관리자를 이용해 프로그램을 설치, 업데이트, 삭제할 수 있다.
- 패키지 관리자는 프로그램 간의 의존성(Dependency)도 관리한다.

**2. 패키지 관리자(Package Manager)**

리눅스 배포판에 따라 사용하는 패키지 관리자가 다르다.

| 배포판 | 패키지 관리자 | 패키지 형식 |
| --- | --- | --- |
| Ubuntu | APT | `.deb` |
| Debian | APT | `.deb` |
| Fedora | DNF | `.rpm` |
| RHEL | DNF / YUM | `.rpm` |
| CentOS | DNF / YUM | `.rpm` |

**3. 패키지 관리 관련 용어**

| 용어 | 설명 |
| --- | --- |
| Repository | 프로그램 패키지를 저장하고 배포하는 저장소 |
| Dependency | 특정 프로그램을 실행하기 위해 필요한 다른 패키지 |
| Package Manager | 패키지 설치, 업데이트, 삭제 등을 관리하는 도구 |
| Package Index | 저장소에서 제공하는 패키지 정보 목록 |
| Update | 패키지 목록 정보를 최신 상태로 갱신 |
| Upgrade | 설치된 패키지를 새 버전으로 업데이트 |

**4. Ubuntu 주요 명령어 (APT)**

| 명령어 | 설명 |
| --- | --- |
| `sudo apt update` | 패키지 목록 업데이트 |
| `sudo apt upgrade` | 설치된 패키지 업데이트 |
| `sudo apt install 패키지명` | 패키지 설치 |
| `sudo apt remove 패키지명` | 패키지 삭제 |
| `sudo apt purge 패키지명` | 패키지 및 관련 설정 파일 삭제 |
| `sudo apt autoremove` | 더 이상 필요하지 않은 의존 패키지 정리 |
| `apt search 패키지명` | 패키지 검색 |
| `apt show 패키지명` | 패키지 정보 확인 |
| `dpkg -l` | 설치된 패키지 목록 확인 |

**5. 명령어 실습**

```text
# 패키지 목록 업데이트
sudo apt update

# 설치된 패키지 업데이트
sudo apt upgrade

# htop 패키지 설치
sudo apt install htop

# 설치된 패키지 정보 확인
apt show htop

# 설치된 패키지 삭제
sudo apt remove htop

# 패키지와 관련 설정 파일 삭제
sudo apt purge htop

# 더 이상 필요하지 않은 패키지 정리
sudo apt autoremove
```

**6. apt update와 apt upgrade의 차이**

두 명령어는 이름이 비슷하지만 역할이 다르다.

| 명령어 | 역할 |
| --- | --- |
| `apt update` | 저장소에서 최신 패키지 목록을 가져온다. |
| `apt upgrade` | 최신 패키지 목록을 기준으로 설치된 패키지를 업데이트한다. |

쉽게 말하면 다음과 같다.

- `apt update` = 어떤 프로그램이 새 버전으로 나왔는지 확인
- `apt upgrade` = 확인한 새 버전으로 실제 프로그램 업데이트

※ `apt update`만 실행한다고 설치된 프로그램이 자동으로 업데이트되지는 않는다.

**7. 패키지와 의존성(Dependency)**

예를 들어 프로그램 A를 설치하는 데 프로그램 B와 라이브러리 C가 필요하다고 가정한다.

- 프로그램 A는 B와 C에 의존한다.
- A를 실행하려면 필요한 B와 C도 설치되어 있어야 한다.
- APT와 같은 패키지 관리자는 이러한 의존성을 확인하고 필요한 패키지를 함께 설치한다.

**8. 핵심 정리**

- Package는 프로그램을 설치하고 관리하기 위한 묶음 단위다.
- Package Manager는 패키지의 설치, 업데이트, 삭제를 담당한다.
- Repository는 패키지를 제공하는 저장소다.
- Dependency는 프로그램 실행에 필요한 다른 패키지를 의미한다.
- Ubuntu에서는 일반적으로 `apt`를 사용한다.
- `apt update`는 패키지 목록 갱신, `apt upgrade`는 설치된 패키지 업데이트다.
